
# Lab 1: Database Choice

## Questions

1. Your Choice: Which database did you select?

    I selected **Azure Cosmos DB Serverless** as the database for storing JSON output generated by the TextAnalyzer Azure Function.

2. Justification: Why is this the best choice for this use case? (3-5 sentences)

    **Azure Cosmos DB Serverless** is a fully managed NoSQL DB designed for high-throughput, low-latency workloads, which perfectly matches the needs of event‑driven Azure Functions that output semi-structured data like JSON objects. Cosmos DB's low‑latency global distribution and automatic indexing via partition keys ensure that the data remains highly queryable and responsive. [1] In addition, its serverless model eliminates the need for fixed throughput setting and it scales automatically and elastically just like classic Functions. As a result, this model is ideal for spiky workloads in a production environment since it charges only for Request Units (RUs) consumed. [2] It maximizes both performance and cost efficiency, since you only pay for what is used, which can often be quite unpredictable with short-lived function calls.

3. Alternatives Considered: What other options did you evaluate and why did you reject them?
    
    1. **Azure Table Storage**: Azure Table Storage is a NoSQL key-value store for simple, non-relational datasets [3] but falls short as it lacks the strong querying/indexing and performance guarantee capabilities of Cosmos DB described above. It is ideal for lightweight metadata and logs, but not so much for analytics we may want to pursue.
    2. **Azure SQL Database**: Azure SQL Database is a fully managed relational database service with strong reliability guarantees, making it ideal when you need structured schema or relational queries joining various tables [4]. However, since our output is JSON which is not structured data, it would be a poor fit for TextAnalysis' needs.
    3. **Azure Blob Storage**: Azure Blob Storage is optimized for storing unstructured binary or text data, not for SQL querying, given that it lacks indexing. [5] Since we want another function to query results, its not suitable for our purposes.
    4. **Cosmos DB (Free Tier)**: In this student lab scenario, the Cosmos DB free tier is the most cost-effective, with the first 1000 RU/s and 25 GB of storage being free for one DB per account. [6] However, for real-world demo purposes I selected the serverless model of Cosmos DB to demonstrate the best option for a realistic enterprise deployment scenario, as the free tier more closely aligns with the allocated thoroughput model where the resources are fixed.

4. Cost Considerations: How does pricing work for your chosen database?

    Azure Cosmos DB Serverless pricing model is **consumption-based** meaning that you only pay for the Request Units (RUs) consumed by operations and storage [2]. You do not have to provision thoroughput beforehand, and the containers can handle thousands of req. per second with no minimum charge. It aligns well with the serverless principles we are exploring in the course.
